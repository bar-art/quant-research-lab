## 学到什么，具体怎么做

| 来源设计 | 本项目的采用方式 | 验证与范围 |
|---|---|---|
| yebof：结构化输出与 Python 硬风控分离 | Pydantic 提议、证据ID、独立 RiskEngine；模型没有改规则的工具 | 越权字段、非法权重、仓位/现金/亏损/回撤测试 |
| yebof：带约束的反思与可追溯运作 | 先做带到期时间的反馈记忆和事务审计 | 不自动修改提示词，不声称实现上游季度自演化 |
| QuantAgents：模拟分析、市场、风险、经理四角色与会议 | 四角色协议和三种会议记录；本地模型可替换规则输出 | 历史绩效仍由规则生成；最新模型会议单独展示 |
| QuantAgents：模拟与市场反馈 | 训练收益压力情景与后续真实走过区间的预测误差分开 | 不把随机情景当成市场实现值；没有RL参数训练 |
| quant-mind：typed knowledge 保留来源与 as_of | available_at、Evidence、数据/源码哈希 | 时间过滤不证明输入来源真实，也不能消除模型预训练记忆 |
| QuantDinger/AstraQuant：完整产品工作流与硬约束 | 采用能复现的端到端报告路径 | 不引入它们的实盘、交易所、账号与部署栈 |

## 相对初始需求的工程改进

这些是本工程选择落实的研究保障，不是在未完整审计的情况下宣称上游项目缺少某项能力：

- 先做无网络、可复现的人工样本，显式区分规则模式与模型模式。
- 每折记录训练候选、选中窗口、样本外表现和试验总数；不把测试表现用于本折选参。
- 数据读取与记忆检索都受可得时点约束，专门测试“偷看明天收益”因子。
- 成交、费用、未成交理由与初始净值均可核对；未知交易限制拒绝成交。
- 预测反馈到期才能进入记忆；只存储/检索，不偷偷修改风控。
- 结构化模型输出仍需要语义边界检查，合法JSON本身不等于正确事实或有效策略。
- 交付报告、CSV、数据库、输入快照、版本和哈希；原始工程不被覆盖。

## 对论文结果的处理

论文报告的实验收益属于作者特定数据、模型与设置。本项目未复现，不作为宣传或绩效目标。论文使用历史测试段与后发布的基础模型；模型训练数据与测试事件的潜在重叠需要另行排除。仅靠本地 as-of 数据过滤不足以证明没有预训练记忆污染，因此本 MVP 不把历史 LLM 交易绩效包装成无泄漏实验。

我们没有照搬论文的模拟/真实反馈自适应权重公式或声称实现强化学习。当前分别报告策略净值与到期预测误差，便于检查反馈来源与时间顺序。IID bootstrap 的 p05/p95 是历史样本假设下的情景统计，不是具有已验证覆盖率的预测区间。
