# 设计与交付边界

本工程为独立新项目，不修改 a-share-quant-agent。定位是可复现的多角色量化研究实验室，不复刻来源仓库的实盘执行系统。

## 数据流与模块

```text
CSV + 数据来源声明 / 固定种子人工样本
  → MarketDataset（结构和时间戳校验）
  → AsOfView（按 available_at 隔离未来数据）
  → WalkForward（只在训练段选择候选窗口）
  → 四角色研究委员会（市场、模拟、风险、经理）
  → 独立 RiskEngine（模型无修改权限）
  → PaperBook（下一交易日开盘、现金约束、费用、不可成交记录）
  → 到期才评分的预测记忆 + SQLite 原子审计
  → CSV / JSON / 自包含 HTML 报告 + SHA256 复现清单
```

- Python3.11，pandas/numpy 做计算，Pydantic 验证角色协议，SQLite 存审计与到期记忆。离线演示无需数据库服务或海外数据源。
- `AsOfView.history(code, end=None)`：拒绝未来日期读取；只返回 available_at <= cutoff 的记录。
- `SimulationAnalyst.evaluate(training, windows, seed)`：候选策略训练结果和基于训练收益的 bootstrap 情景，记录尝试数。
- `Committee.decide(view, selected_window, risk_state)`：三类会议，四个角色，短证据摘要和来源ID，不存储私有思维链。
- `RiskEngine.review(proposal, state)`：数值有限性、标的白名单、单票/总仓位/现金、亏损/回撤阈值。
- `PaperBook.rebalance(...)`：下一开盘模拟成交，先卖后买，卖出受购买日期限制，停牌和封板记录阻断原因。
- `AuditStore.record_session(...)`：会话和相关记忆在同一 SQLite 事务提交；按时点检索已到期记忆。

## 可执行范围

默认demo仍是synthetic人工行情与规则型四角色agent；compare为逐时点Ollama委员会与规则委员会的同条件对照。模型仅返回受限结构化提议；没有 Python eval、终端、文件写入或券商工具权限。compare在每个收盘及换参刷新时调用四角色，开始前检查完整调用预算，错误时终止而不静默换模型。旧--ollama仍只生成末期快照。

模拟撮合允许碎股、统一研究手续费与滑点，不是完整 A 股撮合。不会声称已实现全部板块/IPO例外、手数、印花税/过户费历史、除权处理和退市终值。输入真实数据必须声明来源、股票池历史完整性、公司行动完整性；报告如实标记这些状态。旧 A 股工程 CSV 缺少关键状态和 available_at，不能未经补充直接当作可交易完整历史数据。

## 评估约束

训练选择和测试严格分离；每个测试段结束后才纳入下一训练窗口。每日 t 收盘信号到 t+1 开盘成交。预测评分以真实走过的后续区间计算，评分记忆只在到期后可读。合成样本净值只用于工程验证。bootstrap 情景是历史分布压力诊断，不是未来收益预测。多角色不保证比单角色有效；演示同时报告无模型基线。

大模型预训练记忆仍可能包含历史测试事件，时间戳过滤无法消除这一风险。模型回放要求记录带来源的发布日期，并检查首个决策时点；forward-init/step/settle则先登记、实时记提议、到期才结算。发布后历史回放本身不是已经完成的前瞻测试。数据文件哈希与源码哈希供复现使用，不代表外部数据真实性证明。

逐步升级、真实模型验收与前瞻状态见 [LLM升级实施步骤](LLM升级实施步骤.md)。按用户选择，前瞻股票池暂未确定，工具已实现但没有启动实际市场登记。
